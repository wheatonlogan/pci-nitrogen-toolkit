# NGU Type-X Sales Toolkit (hosted)

The NGU Type-X Sales Toolkit for the PCI Gases sales team, hosted on Railway. It sizes the unit, costs it against delivered liquid nitrogen, and saves projects for the whole team.

This is the offline toolkit v1.6 from the September 2026 Sales Kit, with five changes (v1.7):

| Change | What it does |
|---|---|
| Team login | One shared team password plus each rep's name and email. Replaced by Microsoft sign-in when the app moves into the PCI Hub. |
| Server-side projects | Projects save to Postgres and are shared across the team. Each card shows who saved it last. Offline `NGU Projects.json` files can still be imported and exported on tab 3. |
| Sizing log | Every settled sizing and every save is recorded: rep, flow, purity, pressure, Type and price. Download it from `/api/sizing.csv`. |
| One-page spec sheet | **Print spec sheet**, or Ctrl+P, prints a one-page record: inputs, Type, part number, feed air, compressor, indicative price, payback, rep and date, with the indicative-projection footer. |
| Customer-air note | When the customer supplies the feed air, tabs 1 and 2 and the spec sheet point out that the customer still pays to make that air. |

The sizing and payback math is unchanged from v1.6.

## Layout

```
src/server.js     start-up: migrate, seed stock projects once, listen
src/app.js        routes: /login, /, /api/projects, /api/sizing, /healthz
src/auth.js       signed session cookie carrying the rep's name and email
src/db.js         Postgres: ngu_projects, ngu_sizing_events, ngu_meta
public/toolkit.html   the toolkit page (generated by scripts/hostify.py from v1.6)
public/login.html
public/pci-brand/     PCI brand kit (managed by the pci-web-app skill; don't edit)
seed/projects.json    stock projects (Katrium, AGI) added on first start only
```

## Deploy on Railway

1. Add a **Postgres** database to the project.
2. Add a service from this repo. `railway.json` sets the start command and health check.
3. Set the variables listed in `.env.example`.
4. Generate a domain.

## Tests

```bash
npm install
npm test                                                            # in-memory database
TEST_DATABASE_URL=postgres://user@localhost:5432/ngu_test npm test  # real Postgres
```

Without `TEST_DATABASE_URL` the tests run against an in-memory stand-in for the database (`test/memdb.js`). With it, the run drops and recreates this app's tables in that database, so point it at a scratch database; run it that way before pushing a change to `src/db.js`. The browser tests need Chromium or Chrome. They look for Playwright's download and the usual Linux and macOS installs, or you can set `CHROMIUM_PATH` (or `CHROME_PATH`).

## Changing the model or pricing

The performance tables and pricing constants are in the `<script>` block of `public/toolkit.html` (`FLOW`, `AF`, `COMP`, `P`). Change them there, run the tests, and push. Railway redeploys on push to `main`.
